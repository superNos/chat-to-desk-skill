# 逐轮对话记录（e3-business-analyst）

本文件由演示脚本从会话事件中机械提取，未做改写：

- “本轮开始时工作目录里的文件”由脚本在每轮开始前列出，表示 Agent 在本轮能看到的全部场景材料；
- “演示人输入”是每轮发给 Agent 的原文；
- “Agent 回复”是该轮最后一条消息原文；
- “Agent 读写的文件”是该轮 Agent 自己执行的命令首行（超过 170 字截断）和写文件操作。会话事件不记录文件改名，改名可对照相邻两轮开始时的文件列表看出。

临时工作目录替换为 `<演示目录>`，临时配置目录替换为 `<演示配置目录>`，技能文件位于 `<演示配置目录>/skills/personal-agent-workbench/`。

1. **可以看哪些对话？** 建议先看最近 4 周里，你用 Agent 回答同事临时数据问题的对话。有没有要跳过的主题？你同意后，我会先列出范围内的标题，等你确认这批选得对，再读正文。

### Agent 回复

我建议先用一份放在本机的文档来管理这件事，不做看板，也不做网页。草案已保存到 `output/工作台使用说明（草案）.md`，还没有开始搭建。

**草案包含两样东西：**

- **指标口径：** 每次开始或接着查询时，都附上已确认的口径。目前只有“活跃会员：近 30 天有消费”，用来减少口径用错。
- **同事数据问题记录：** 每个问题记一行，写明提问同事、所提问题、查询所在的对话位置和答复情况。答复情况分为未答复、答复已备好待你转发、已转发三档。只有你说已经亲自转发，才标为“已转发”。

**平时这样用：**

- **同事提出新问题：** 新开一段查询对话，只带用到的口径和查询思路。
- **接着上次查询：** 平台可以把新增条件送回原对话，但每次发送前都会先给你看。
- **找回上次的问题：** 同一位同事再问时，在记录里查上次的提问日期和对话位置。
- **取回结果：** 系统还不能确认能否从原对话自动取回结果，所以需要你把结论带回来，或者告诉我结果已经备好。

原始数据和含销售额明细的附件不会放进任何交接内容。记录里只写对话位置，不写销售数字。提问同事建议用你平时的简称，不记联系方式。

**还需要你决定：**

1. 第一轮先试哪几样？可从“指标口径”“同事数据问题记录”“接着上次查询”中选一到三样。
2. 试用多久？说不清也可以，我会把试用时长记为待定。

还有三件事暂时没定：口径具体用于哪些分析，同事再问时是否沿用上次的答复，记录保留多久。
