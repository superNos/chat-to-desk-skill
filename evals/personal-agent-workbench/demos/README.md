# 前向演示：两个非开发用户用同一技能得到的工作台

**这是评估演示，不是默认模板。** 这里的文档、栏目、状态和页面只属于两位虚构用户，不能照搬给其他用户，技能文件也不引用本目录。真实使用时，工作台要按当前用户自己的历史和确认结果重新推导，结论也可能是不需要工作台。

所有人物、学生代号、同事代号、日期、对话和页面数据都是虚构的。

## 演示怎么做

| 项目 | 做法 |
| --- | --- |
| 扮演 Agent 的会话 | 每个场景在独立的临时目录里新开一个 Codex 会话。配置目录也是临时的，只装 `skills/personal-agent-workbench/`，不加载维护者的全局说明和其它技能，不继承维护者的任何对话上下文。之后每轮在同一会话里续接 |
| Agent 能看到的材料 | 技能文件；授权之后放入的 `platform/`（只含该场景的授权范围、平台四项能力核实结果和虚构历史摘要）；Agent 自己写出的 `output/`。每轮开始时工作目录里有哪些文件，记在 `transcript.md` |
| Agent 看不到的材料 | 场景文件里的 `expected`、`usage_probes`；另一个场景的任何内容；本目录 |
| 用户的回答 | 演示人只转述场景文件 `authorization` 和 `user_calibration` 里的预设回答。预设里没有的问题一律答“说不清”“按你的建议”，或只做流程上的同意（如“可以，请给我看草案”“好的，就按这个试”）。Agent 每次给的发现条目编号不同，演示人按对话编号（H1…）把预设回答对到相应条目上 |
| 隔离 | 两个场景各用一个临时目录、各自的会话，互不读取对方的产物 |
| 产物 | Agent 自己写在 `output/` 的文件原样复制到 `agent-output/`；截图由本机 Chrome 无头模式对 `preview.html` 截取，截图前已人工查看渲染；`transcript.md` 由脚本从会话事件中机械提取（临时工作目录替换为 `<演示目录>`，临时配置目录替换为 `<演示配置目录>`） |

最后一轮里，演示人另外要求 Agent 生成 `preview.html` 和 `过程记录.md`。这两项是评估需要，技能本身不要求。预览只能如实呈现 Agent 已选定的工作台，不得新增说明里没有的元素。两位用户实际得到的都是本机文档，预览页把文档按页面样子呈现，页面上写明了实际形式。

两个场景的轮数不同：E3 的 Agent 先只列标题、请用户确认读法，又在草案之后单独定了试用范围，所以比 E1 多一轮。

**与本发布包技能文字的差别。** 演示是在技能的开发仓库里运行的。当时的技能文字有四处提到维护者另外两个面向开发者的技能（多 Agent 开发总控和它的本地台账页面）：`SKILL.md` 的说明和“与其它技能的关系”一节、`cases.md` 的开发总控案例、`quality-checks.md` 的一条反模板检查、`platform-adaptation.md` 的 Codex 线索。本发布包不含那两个技能，所以把这四处改成了不依赖它们的说法，意思不变：只有用户的工作确实是开发总控时，才把现成的任务台账作为可选项提出。其余技能文字与演示时相同。两个演示的用户都不是开发者，他们的会话记录里没有用到这几处内容。

## 运行记录

两个场景一共从头运行了九次。本目录只保存第九次的产物，前八次的产物已随临时目录删除。每次发现问题，都先改技能，再从头重跑，没有手工修改产物。

| --- | --- | --- |

| 8 | 开发方检查发现：E1 草案把“要不要标出哪些还没回”留成开放问题，老师答“说不清”，于是已确认的“常常同时有好几条没回”没有得到任何对应做法 | workbench-design.md 第 4 节：每件已确认的麻烦，草案里要么给出做法，要么写明暂缓及理由；用户答“说不清”或“按你的建议”时，由 Agent 给出建议再请他确认。第 5 节：工作台说明必须包含示例里的每一节 |

### 偏差，如实记录

- **E1 的试用版比确认过的草案多了一种状态，且没有先征得同意。** 草案（`transcript.md` 第 4 轮）写明“每条消息只记四种情况：还没回；交接内容已备好，等你自己粘贴；草稿已拿回，等你改完自己发；你已发出”，老师在第 5 轮回答“这三样可以，没有要删改的”。搭建出来的《家长沟通记录》和《工作台使用说明》在“等我粘贴”和“草稿已拿回”之间，加了“已贴到对话，最新情况未知”。这一档本身符合技能的状态规则（只确认粘贴、看不到进展时不能说已开始），但对话里看不到 Agent 在搭建前说明这项改动，不符合 `quality-checks.md` 的“试用版与确认的草案一致，改动先说明并取得同意”。技能里已有这条规则，是这次运行的 Agent 没有做到；我们保留原产物，没有为此重跑。
- **E3 的第一次使用说明没有讲“工作台不一定是软件，结论也可能是不需要”。** 技能的第一次使用示例里有这句话。E3 的 Agent 只说“一起决定怎样整理最省事”。后续结论仍是选了最轻的本机文档，没有因此做多。
- **E3 的发起和继续能力已核实，试用版仍写“手动发送”。** 原因是试用版是一份文档，没有发送入口，Agent 在使用说明里写明了这一点。
- **E1 的周五通知开场说明只给在对话里**，`transcript.md` 第 4、5 轮能看到原文，`agent-output/` 的文件里没有写格式原文，这是因为老师没有同意长期保存（R1 待问）。
- **预览里的行和交接示例都是 Agent 编的虚构例子**，如“练习甲”“示例周四”“按周看复购率”。它们只用来演示填法，不来自历史，页面上标了“虚构示例”。两份正式记录都留有空白填写区；E3 的《同事数据问题记录》在空白表下面另附了四行标明“全部虚构”的填写示例。
