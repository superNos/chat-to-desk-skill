# 过程记录

## 各轮问答

1. 初次询问可读范围、排除主题、发现存放位置和期限。用户授权读取该平台最近四周的对话，无排除主题，允许本机保存发现，期限说不清。演示指定 `output/`。用户同时限定，给 Agent 的家长消息只能是摘要，不能含学生全名和家长电话。
2. 读取 10 条摘要后，逐项询问家长回复是否由老师本人发送、两类过往沟通是否都值得找回、通知格式的适用范围、出游是否只是偶尔询问，以及是否长期保存通知格式。用户确认起草回复和查找过往沟通，补充每周有十几条家长消息，常同时有几条未回，按学生找最麻烦。今后是否都由本人发送说不清。通知限学期中每周五，格式是否长期保存说不清。出游与工作无关。
3. 复述修正后的理解并请确认。用户确认并要求看草案。
4. 给出家长消息、按学生查找、周五通知的草案，建议首版先试前两项，并请确认范围和位置。用户确认在 `output/` 搭建。交付时请用户试用后反馈查找和交接是否顺手，本次记录时尚无试用反馈。

## 首版元素与依据

| 元素 | 依据与取舍 |
| --- | --- |
| 还没回的家长消息、新消息入口、摘要 | W1（H1、H2、H4、H6），结合用户自述的消息量和同时有多条未回。以是否实际回复家长决定是否留在该区。 |
| 学生代号、按代号查找、按日期查看摘要和回复 | W2（H5、H8），结合用户确认按学生找最麻烦。代号只用于本机查找。 |
| 起草、补充、选定草稿版本修改、原对话位置 | W1（H1、H2、H4、H6）和 W2（H5、H8），并经草案确认。原对话位置只记在本机，补充和改稿由用户粘贴回原对话。 |
| 每次确认摘要和写作要求、复制交接、确认已粘贴、粘贴回稿 | W1（H1、H2、H4、H6）及用户明确的材料边界。平台能力核实只支持读取历史，发起、继续和取回待核实，所以使用手动交接，草稿回到同一条消息。 |
| 交接状态、状态依据、实际回复记录 | W1（H1、H2、H4、H6），结合用户自述有多条消息同时未回。区分交给 Agent、拿到草稿和发给家长，实际发送由用户确认后记录。 |

## 留在首版之外的内容

- 周五通知（W3，H3、H7、H9）进入草案，用户选定首版只试家长消息和按学生查找。固定通知格式的长期保存仍未获确认。
- 个人出游（W4，H10）经用户明确为与工作无关。
- 自动发起、继续对话和取回草稿缺少对应平台能力的核实。自动给家长发送也没有针对具体发送的授权，用户对将来是否都本人发尚未确定。
- 学生全名、家长电话和家长消息原文没有进入交接。用户只允许交经确认的摘要，学生代号也按确认的草案留在本机。
