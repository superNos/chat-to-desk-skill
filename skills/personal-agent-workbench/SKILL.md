# 个人 Agent 工作台

调用 `$personal-agent-workbench` 时，先弄清用户平时办哪些事、怎样办完，再把已确认的做法变成可操作的本机工作台。打开工作台后，用户应当能选中工作对象、发起操作、看到实际进展，并在原处找回结论。

首次生成按下面的顺序推进。调整已有工作台时，从受影响的步骤开始，沿用已确认的工作模型、草案和授权。需要用户决定的是授权范围、对工作的理解和首版草案；同一决定已有明确答复时直接沿用。用户随时可以修正或停止。

## 1. 从授权历史还原工作

第一次先用用户听得懂的话说明用途，问清可以看哪些来源、时间和排除项，发现只在本次对话展示还是保存到指定的本机目录。得到授权后，核实历史可见范围，遍历范围内全部可访问对话，交代缺失部分。读不到历史或用户选择跳过时，可用用户提供的样例或访谈，注明依据来自自述。[历史分析与工作模型](references/history-analysis.md)

按有证据的日期还原活动，把不同对话里指向同一交付目标的工作合成一个事项。一次明确交付也可以是工作；零散咨询、消息数量和日期空白都不足以推出待办或日程。让用户用自己的叫法校准目标、做法和完成条件，再选择首版要办的事。[用户校准](references/calibration-interview.md)

## 2. 决定工作台上放什么

| 历史和用户校准说明了什么 | 在工作台里怎样处理 |
| --- | --- |
| 具体事项仍有范围内的工作 | 围绕该事项放下一步操作和最近结论。 |
| 事项已达到交付终点 | 退出当前工作，按授权保留可找回的结果。反复修改同一事项仍算一次。 |
| 同一做法在不同事项中复用，或用户明确以后还会用 | 提炼成常用功能，内置固定步骤，只让用户选择对象、填写变量、作必要决定。 |
| 有一次性的安排或例外 | 提供能指向新事项或原事项的输入入口。工作零散时，一个发起入口和一处结果记录就足够。 |

为每个候选功能说清触发条件、输入、稳定步骤、人工决定和交付物。沿用用户已有的成功做法，只保留用户约定、实际授权和执行依赖所需的检查与提醒。[工作流抽象](references/workflow-abstraction.md)

## 3. 设计用户实际会操作的页面

首版通常由用户选一到三类工作。用一件真实事项讲清从哪里开始、点什么、在哪里判断结果。页面分区、字段和名称应能追溯到已确认的工作；用户已有合用工具时，和用户决定沿用或接入哪一部分。不同用户可以有完全不同的布局。

按当前难题选协作技能：候选功能多时用功能规划，步骤和交接不清时用产品设计，业务路径明确后用前端设计落实排版。按宿主实际可用能力选择。[协作 Skill 选择](references/skill-selection.md)

新建或整体改版采用成熟组件库或宿主设计系统。按对象排列列表、主要动作和结果，让用户先读到结论及重要限制，可比数据用表格，依据按需展开。给用户看草案，确认后再搭建。[工作台设计与说明](references/workbench-design.md)

## 4. 接通 Agent 并在本机交付

根据用户平时办理该事项的项目绑定目标，优先采用用户明确指定的项目。固定在同一对话办理的工作复用原对话，分别记录每次执行。涉及只读联网或完整编号查询时，在实际执行环境核实来源和对象。[平台适配](references/platform-adaptation.md)

让页面直接发起获准的业务操作，把真实进度和最终结论自动带回对应事项、步骤和轮次。依据宿主回执区分排队、开始、完成和失败；断线保留最后已知情况。缺少发送或回传连接的动作禁用，并说明缺哪一环。[输入、状态与结果](references/agent-interaction.md)

使用附带的运行支持，将生成的页面、配置和记录放在用户指定的本机目录，与公开 skill 分开。本机无法运行时按设计指南选等效做法。至少用一项获准的真实工作走通页面发起、自动回传和重开找回，才能交付可执行的工作台。只验证通信时如实说明验证范围。[本机搭建](references/runtime.md) · [交付验收](references/quality-checks.md)

## 授权与后续维护

- 分别确认分析历史、长期保存规则、把材料交给 Agent 执行的权限。仅获准分析时，发现只在当前对话展示。获准保存发现时只记必要概括和来源引用；规则和固定背景另按保存规则的授权处理。
- 在用户确认草案和本机目录后生成工作台及使用说明。未获准保存发现时，说明里的依据只写条目编号和确认状态。凭据及第三方敏感资料不进入工作模型或说明。用户要求删除时按范围处理。
- 对外发送、提交、推送、付款、发布或删除等有外部影响的动作，按本次明确授权执行。历史习惯不能代替本次同意。
- 用实际使用记录提出调整，由用户决定是否采用。[持续调整与规则管理](references/evolution.md) 需要理解证据如何导向不同布局时，再读[虚构案例](references/cases.md)。
