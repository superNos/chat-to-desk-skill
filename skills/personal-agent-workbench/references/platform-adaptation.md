# 平台适配：逐项核实四项能力

目标：只基于在用户当前环境里核实过的能力设计交接方式；没核实的，用可复制的交接内容兜底。

## 四项能力

| 能力 | 问题 |
| --- | --- |
| 读取历史 | 你能否在用户授权下读到他过去的对话内容？能读到多少、什么格式？ |
| 发起工作 | 能否从工作台新开一个对话或任务，并把交接内容送进去？ |
| 继续同一工作 | 能否把补充或修改送回原来那个对话，而不是新开一个？ |
| 取回结果 | 能否读到那个对话里这次工作的结果，并带回工作台？ |

四项分别记录，不能因为一项可用就假设其它项可用。

## 怎样算核实

只有一种算核实：在用户当前的平台、版本和账号环境里，实际做一次最小操作并看到结果。例如在用户同意的测试对话里发一句无害的话，再读回来。

官方说明、工具列表里有对应命令，只能作为去试的线索，试过之前仍记为待核实。以下也都 **不算** 核实：平台名称、宣传介绍、你的记忆、其它用户的经验、旧版本的说明、本技能案例里的写法。

做测试操作本身也要用户同意，并且只用无害内容，不发给他人。

读取历史的核实与分析授权放在一起：用户同意分析后，先只尝试列出授权范围内的对话标题和日期，能列出就记为已核实，再开始阅读；列不出就改用粘贴或访谈。

## 记录格式

写进工作台说明的“平台能力”一节：

```markdown
| 能力 | 结果 | 核实方式 | 平台与版本 | 日期 |
| --- | --- | --- | --- | --- |
| 读取历史 | 待核实 | — | — | — |
| 发起工作 | 已核实 | 在测试对话中发起并看到回复 | 某平台 某版本 | 2026-01-16 |
| 继续同一工作 | 不支持 | 只能新开对话 | 某平台 某版本 | 2026-01-16 |
| 取回结果 | 待核实 | — | — | — |
```

结果只用三种：已核实、不支持、待核实。平台升级或用户换环境后，把相关项改回待核实再查。

## 各平台的起点

所有平台都从“四项待核实”起步。

- **Codex**：本技能的维护者曾在 codex-cli 0.169.x 至 0.170.x 上，用本地命令把消息送入指定对话、读取对话输出。这只是可以去核实的线索，不代表用户的版本也支持，更不代表其它 Codex 产品形态（网页、桌面应用）的能力相同。它与工作台该有什么内容无关。
- **Claude、WorkBuddy 和其它平台**：本技能不对它们的历史读取或对话接口做任何判断。按上面的方法在用户环境里核实；查不到可靠说明时保持待核实。

## 能力缺失时的降级

| 缺少的能力 | 做法 |
| --- | --- |
| 读取历史 | 请用户粘贴或导出少量示例，或改为访谈 |
| 发起工作 | 生成交接内容，用户复制到新对话；状态为需手动完成 |
| 继续同一工作 | 交接内容写明“请在原对话中粘贴”，并提供原对话的可定位描述 |
| 取回结果 | 在对应位置写明结果在哪里，请用户复制回来 |

降级不是失败。很多用户只用手动交接就能得到大部分好处，因为背景和去向已经整理好。
