# 平台适配：逐项核实四项能力

目标：为当前 Agent 接通用户授权的执行与回传路径，逐个验证可用的业务动作。

## 四项能力

| 能力 | 问题 |
| --- | --- |
| 读取历史 | 你能否在用户授权下读到他过去的对话内容？能读到多少、什么格式？ |
| 发起工作 | 能否从工作台新开一个对话或任务，并把交接内容送进去？ |
| 继续同一工作 | 能否把补充或修改送回原来那个对话，而不是新开一个？ |
| 取回结果 | 能否读到那个对话里这次工作的结果，并带回工作台？ |

四项分别记录，不能因为一项可用就假设其它项可用。

## 怎样算核实

只有一种算核实：在用户当前的平台、版本和账号环境里，实际做一次最小操作并看到结果。例如在用户同意的测试对话里发一句无害的话，再读回来。

用 Codex 时，可以用运行支持的 `codex-probe` 命令做这次最小操作，见 [runtime.md](runtime.md) 第 6 节。

官方说明、工具列表里有对应命令，只能作为去试的线索，试过之前仍记为待核实。以下也都 **不算** 核实：平台名称、宣传介绍、你的记忆、其它用户的经验、旧版本的说明、本技能案例里的写法。

先把用户确认的动作逐项对应到当前 Agent 实际可调用的工具和目标，核对页面能否调用同一条路径。一次明确授权的真实工作也可以用来核实：在用户指定的已有业务对话，使用本次同意的材料执行一次，只记录实际观察到的能力。另做连通测试须经同意并使用无害内容。分析历史的授权不能用于发起工作。

读取历史的核实与分析授权放在一起：用户同意分析后，先只尝试列出授权范围内的对话标题和日期，列出后，读取范围内的实际消息或结果再记为已核实，并注明可见范围。只能看到标题时说明限制，请用户提供缺失的材料；其它可读来源继续分析。

## 只读任务怎样取得指定事项

生成查询步骤时，分别确定可以读取哪些文件、是否需要访问远端、允许读取哪个来源及对象。优先使用已授权的只读连接器。若由 Agent 直接查询，把文件只读和所需网络访问配置在实际执行的目标与轮次上，沿用宿主的审批和访问限制。若宿主只能通过放开文件写入或扩大授权范围才能联网，保留只读边界并报告缺少的能力。认证交给已有客户端，结果和日志里只留查询所需的业务字段。

用本次已授权的查询验证连接。服务返回详情才能证明该账号可读该事项。遇到解析或连接失败时，在执行任务的环境核对网络策略与目标可达性。登录失效或账号无权读取时，记录对应原因。工作台所在电脑能打开页面，只能说明那台电脑可达。

用户给出完整编号时，优先使用来源提供的按编号查详情功能。若详情接口只接受内部 ID，先在授权范围内用完整编号搜索，覆盖相关状态和分页，再精确核对返回编号与所属范围。仅在唯一匹配时使用来源返回的内部 ID 取详情，并再次确认对象归属。保留编号的前缀、分隔符与前导零。默认待办、最近记录或本地摘要未命中时，继续查权威来源。授权范围内无匹配、匹配不唯一或查询未完成时，分别说明情况，停在当前步骤。

例如，已归档的申请可能不会出现在在办列表中。按申请编号取回对应详情后，工作台才能报告该申请的实际状态。

## 记录格式

写进工作台说明的“平台能力”一节：

```markdown
| 能力 | 结果 | 核实方式 | 平台与版本 | 日期 |
| --- | --- | --- | --- | --- |
| 读取历史 | 待核实 | — | — | — |
| 发起工作 | 已核实 | 在测试对话中发起并看到回复 | 某平台 某版本 | 2026-01-16 |
| 继续同一工作 | 不支持 | 只能新开对话 | 某平台 某版本 | 2026-01-16 |
| 取回结果 | 待核实 | — | — | — |
```

结果只用三种：已核实、不支持、待核实。平台升级或用户换环境后，把相关项改回待核实再查。

## 各平台的起点

所有平台都从“四项待核实”起步。

- **Codex**：本技能附带的运行支持有一个 Codex 适配器，通过本机的 `codex app-server` 把交接送进用户指定的对话、读回这一轮的回复。维护者自述：在 codex-cli 0.170.0 上，用隔离的临时配置目录和只用于测试的临时对话，用 `codex-probe` 核实过发起和取回各一次，又通过工作台页面接口交付过一次新工作和一次继续同一工作，状态依次为已发送、已开始、已完成，都取回了回复。测试对话和记录没有随发布包公开。这只是可以去核实的线索，不代表用户的版本也支持，更不代表其它 Codex 产品形态（网页、桌面应用）的能力相同。它与工作台该有什么内容无关。
- **Claude、WorkBuddy 和其它平台**：本技能不对它们的历史读取或对话接口做任何判断。按上面的方法在用户环境里核实；查不到可靠说明时保持待核实。

优先接入当前宿主已授权的本机接口或适配器。页面到执行目标的收发链路都要核实；只在对话中能调用某工具，还不足以启用页面按钮。

## 能力缺失时的降级

| 缺少的能力 | 做法 |
| --- | --- |
| 读取历史 | 请用户粘贴或导出少量示例，或改为访谈 |
| 发起工作 | 禁用新工作入口，说明待接通的目标 |
| 继续同一工作 | 禁用对应续办入口，保留既有记录 |
| 取回结果 | 禁用依赖该回传能力的执行；已发送的工作保留最后证据并按原轮次重查 |

所有候选动作都未接通时，报告交付受阻及缺失能力，继续寻找宿主允许的直接连接。
