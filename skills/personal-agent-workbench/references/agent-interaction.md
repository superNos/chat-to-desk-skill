# 工作台与 Agent 的交互约定

每个工作台都遵守下面的约定。约定是共同的，页面上怎样实现（放在哪、叫什么）由每个用户的工作台决定。用附带的运行支持时，其中一部分由运行支持保证，见 [runtime.md](runtime.md)。

## 1. 每个输入都有去向

用户提交任何输入前，都要明确它是哪一种：

| 去向 | 含义 | 要带上的 |
| --- | --- | --- |
| 新工作 | 开始一件之前没有的事 | 必要背景、要求、期望结果 |
| 继续某件事 | 对已有工作补充或推进 | 是哪件事、在哪个对话、补充了什么 |
| 修改结果 | 改一个已经产出的结果 | 是哪个结果、哪个版本、改什么 |

放在某个对象旁边的输入，默认指向这个对象；通用输入要让用户选去向。去向不明时（例如“把上次那个改一下”对应多个结果）列出候选请用户选，确认前不发。

## 2. 在工作台里交给 Agent，或者生成交接内容

平台能力已核实（见 [platform-adaptation.md](platform-adaptation.md)）、并且工作台有对应的交付方式时，在工作台里直接把输入交给对应对话。未核实、不支持，或工作台没有这个平台的交付方式时，工作台生成一段可以直接复制粘贴的交接内容，显示“需手动完成”，并写明应该粘贴到哪个对话；用户粘贴后在工作台里点“已粘贴”，状态才变为已发送。

交接内容至少包含：

```text
【去向】修改结果：东街门面租赁合同 第 3 版
【背景】按所里惯用的条款写法；只改指定条款，其余不动
【这次要做】第 7 条违约金改为按月租金计算
【完成后给我】修改后的第 7 条，以及与第 3 版的差异说明
```

交接内容只放这次工作需要的材料。材料是否可以交给这个对话或 Agent，看“交给 Agent 执行”的授权，由用户自己复制粘贴的交接内容也一样。“背景”一栏里写的东西也算交出的材料，包括用户的身份、单位、岗位和对象代号；用户只授权交出某类材料时，背景只能写这类材料本身和不含个人信息的工作要求（例如“只起草，我自己发”），不要预填用户在当前对话里讲过的个人背景。还没有这项授权、或者这份材料不在授权范围内时，生成前先告诉用户里面会包含哪些材料（例如订单代号、对方消息原文），取得同意后再生成；用户不同意的材料不放进去。生成了交接内容不等于已经发送。

上面的四个标签是建议写法，可以换成用户习惯的说法，但去向、背景、这次要做、期望结果这四样内容都要有。

## 3. 结果回到对应位置

结果要回到发起它的那件事或那个对象上，让用户从同一个地方找到：

- 能自动取回时，写回对应对象，并保留与上一版的关系；
- 不能自动取回时，在对应位置写明“结果在哪个对话里，需要手动带回”，并在那里放一个粘贴框，让用户把对话里的结果复制后粘贴回来；粘贴回来的结果标明“你粘贴回来的”。

不要把结果堆到一个与发起位置无关的总列表里，除非用户确认就是这样找东西。

## 4. 状态如实显示

只使用用户工作需要的状态，但凡用到下面这些，就按证据区分，不能合并或拔高：

| 状态 | 需要的证据 |
| --- | --- |
| 已发送 | 平台确认交接已送达；手动交接时为用户确认已粘贴发送 |
| 已开始 | 有证据显示 Agent 已开始处理，例如出现了这次工作的回复 |
| 已完成 | Agent 产出了这次要的结果 |
| 待确认 | 结果或下一步需要用户决定（发送、提交、选择版本等） |
| 失败 | 有明确的失败信息 |

另外两种情况要直接说出来：

- **需手动完成**：只生成了交接内容，还没发出；
- **无法确认**：拿不到最新情况，保持上一个有证据的状态，并标明“最新情况未知”。

没看到回复、没拿到结果、等了很久没有动静，都不是失败，按“无法确认”处理；只有平台或 Agent 给出了明确的失败信息（报错、拒绝、发送不成功）才写失败。取回能力未核实时尤其要分清，否则用户会把同一件事重复发起。

从保守到乐观的顺序是：需手动完成 → 已发送 → 已开始 → 已完成。拿不准时选更靠前的那一个。待确认、失败、无法确认不在这条线上，按各自的证据单独显示。

常见错误：把“已排队”说成“处理中”；把“Agent 已完成草稿”说成“事情已办完”；把“已生成交接内容”说成“已发送”。

## 5. 每次单独确认的动作

下面这些动作有外部影响，每次执行前都要用户对这一次明确确认：

- 发送消息、邮件或评论给他人；
- 提交、推送、合并代码，部署或发布；
- 付款、下单、退款；
- 删除或覆盖用户的数据；
- 对外提交表单、审批或上报。

确认不能从历史习惯、已保存的规则、以前的类似确认或工作台本身的设计推断。用户说过“以后这类直接发”时，把它记为偏好，并告诉用户它不能代替每次确认。工作台上把这类动作做成需要用户自己操作的那一步，不做自动执行。

## 6. 学到的规则不扩大授权

规则只描述做法和偏好（格式、语气、术语、先后顺序），不能授予发送、提交、付款、发布、删除、扩大历史读取范围等权限。规则的保存、修改和删除见 [evolution.md](evolution.md)。
