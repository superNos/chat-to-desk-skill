同一个技能，两个不同的工作台

两位虚构用户都不是开发者。两个互不相通的新会话各自按同一份技能，读这位用户的历史、和用户校准，再提出工作台。

小学班主任家长消息很多，常常几条同时没回；想按学生找以前怎么回的业务分析师同事随时来问数据；指标口径反复讲、怕用错；常接着上次的查询继续
得到什么 浏览器里的“家长沟通工作台” 浏览器里的“临时数据问题工作台”
围绕什么 一条条家长消息（学生代号＋摘要）。顶部是“还没回的家长消息”，下面可以按学生代号找以前的沟通 一个个同事问题（名称＋指标）。顶部是已确认的口径“活跃会员 · 近 30 天有消费”，下面每个问题标“待答复”或“已答复”
在哪里输入 记一条新消息
每条消息下：请 Agent 起草/补充这条消息/修改第 N 版
输入里像电话号码的内容会被拦下		 新建问题，指标只能选活跃会员或复购率
每个问题下选：新开查询/接着查/修改结果
填原对话位置、指标口径和查询思路
状态 每次交接：需手动完成已发送（最新情况未知）待确认
回家长另记一步：已记录发给家长		 每次交接：需手动完成已发送（最新情况未知）待确认
问题本身另记：待答复已答复
结果回到哪 粘贴回同一条消息下，按版本保留；实际发给家长的话在老师确认后另记一笔 粘贴回发起交接的那个问题下；“接着查”要贴回原来那个对话
授权边界 每次交接前确认：只交摘要，没有学生全名、家长电话和学生代号；给家长发送由老师本人完成 每次交接前确认：只交口径和查询思路，原始数据留在本机；只有口径获准长期保存；转发给同事由她本人做
没有加入 周五通知（她选了首版不试）、自动发送和取回、代发按钮 部门看板（她明确否定过）、自动转发、“旧结果难找”的专门入口（她说不清）

两个平台的发起、继续、取回能力都没有本机程序能调用的接口，所以都走“复制交接 → 点已粘贴 → 把结果粘贴回来”。完整依据见 evals/personal-agent-workbench/demos/comparison.md。
