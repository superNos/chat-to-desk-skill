## Purpose

让用户自己的 Agent 在用户明确授权的范围内阅读历史工作，整理成带证据、可由用户校准的工作模型，作为后续设计工作台的唯一事实来源。

## ADDED Requirements

### Requirement: 分析前确认授权范围
技能 SHALL 要求 Agent 在读取任何历史对话或工作材料前，先向用户说明并取得授权：读取哪些来源、时间范围、排除哪些对话或主题、分析结果保存在哪里、保存多久。未取得授权时，Agent MUST NOT 读取历史材料。授权 MUST 只覆盖用户明确列出的范围，Agent MUST NOT 根据“方便”“可能有用”自行扩大。

#### Scenario: 用户尚未授权
- **WHEN** 用户第一次调用技能，只说“帮我整理一下工作”
- **THEN** Agent 先用普通语言说明要读什么、存什么、不会做什么，并请用户选择来源和时间范围，在用户回答前不读取任何历史对话

#### Scenario: 用户排除部分内容
- **WHEN** 用户授权读取最近两个月的对话，但要求排除涉及家人健康的对话
- **THEN** Agent 跳过被排除的内容，在工作模型的授权范围中记录这项排除，且不在任何结论中引用其内容

#### Scenario: 分析中发现需要更多材料
- **WHEN** Agent 认为授权范围外的某个来源可能有帮助
- **THEN** Agent 说明原因并单独询问，用户同意前不读取该来源

### Requirement: 三类授权分别取得
技能 SHALL 把“分析历史”“保存学到的规则”“把材料交给 Agent 执行”视为三项独立授权。任何一项授权 MUST NOT 被当作另外两项的授权。

#### Scenario: 已授权分析但未授权保存
- **WHEN** 用户同意分析历史，但没有同意保存规则
- **THEN** Agent 只在当前对话中展示发现，不把规则写入任何持久记录，并询问用户是否需要保存

#### Scenario: 同意保存发现但未同意保存规则
- **WHEN** 用户同意把观察和证据保存为本地记录，但没有被问过或没有同意保存规则
- **THEN** Agent 只保存观察和证据，学到的规则和需要长期保存的背景资料在记录中只留编号并标为待问，原文只在当前对话中展示，不作为已保存内容使用

#### Scenario: 已保存规则不等于可以转交材料
- **WHEN** 工作模型中已保存了“客户稿件按段落编号”的规则，工作台需要把某份稿件交给另一个 Agent 对话
- **THEN** Agent 在转交前单独确认这份材料可以交出，不以已保存的规则作为转交授权

### Requirement: 工作模型的每条判断都有证据
技能 SHALL 要求 Agent 把分析结果整理为工作模型。每条观察 MUST 写明证据来源（以对话标题、日期或用户自述等可定位的方式描述，不复制敏感原文）、出现次数或频率、当前校准状态。Agent MUST 区分“直接观察到的事实”和“推测”，推测 MUST 标为待校准。

#### Scenario: 记录一条重复工作
- **WHEN** Agent 在 6 个对话中看到用户每次都重新说明同一份客户术语要求
- **THEN** 工作模型记录这条观察、引用这些对话的可定位描述和次数，状态为待校准

#### Scenario: 证据不足的推测
- **WHEN** Agent 只在 1 个对话中看到某种工作
- **THEN** 该条目被标为线索或待校准，不作为已确认的重复工作进入设计

### Requirement: 用户校准后才进入设计
技能 SHALL 要求 Agent 用用户自己的说法展示主要发现，并让用户对每条发现选择确认、修正、否定或限定范围。工作台设计依据 MUST 只来自用户确认、修正或限定范围后的条目（限定范围的条目只在该范围内使用）；被否定的条目 MUST NOT 再被引用。Agent SHALL 询问是否有历史中看不到、但对工作重要的内容。

#### Scenario: 用户否定一条发现
- **WHEN** 用户说“周五整理数据只是那段时间临时做的，以后不做了”
- **THEN** 该条目状态改为已否定，后续设计不为它增加任何功能

#### Scenario: 非开发用户参与校准
- **WHEN** 用户不熟悉技术术语
- **THEN** Agent 用日常工作语言描述发现（例如“你常常需要找回上次给客户的修改版”），不要求用户理解字段、接口或页面结构

### Requirement: 允许没有历史或历史不足
技能 SHALL 支持历史不可读取、用户不愿授权或历史太少的情况。此时 Agent MUST 改用访谈或用户提供的示例建立工作模型，并如实说明证据来源是用户自述；证据不足以支持设计时，Agent MUST 明确说出这一点，不用通用假设补齐。

#### Scenario: 平台无法读取历史
- **WHEN** 用户使用的平台没有已核实的历史读取能力
- **THEN** Agent 说明这一限制，提供让用户手动粘贴或导出少量示例的方式，或改为访谈，并把证据来源记为用户提供

#### Scenario: 先授权再核实读取能力
- **WHEN** Agent 尚不知道当前平台能否读取历史
- **THEN** Agent 先说明并取得分析授权，再只尝试列出授权范围内的对话标题来核实；授权前不做任何读取尝试，也不向用户承诺一定能读到历史

### Requirement: 分析结果最小化保存
技能 SHALL 要求工作模型只保存设计所需的概括、计数和可定位引用。Agent MUST NOT 在工作模型中保存密码、令牌、账号、证件号码、完整联系方式、付款信息或第三方的个人敏感信息；遇到这类内容时 MUST 只记录“存在某类敏感内容”并提醒用户。用户要求删除时，Agent MUST 删除对应记录并告知删除了什么。

#### Scenario: 历史中出现敏感信息
- **WHEN** Agent 在授权历史中看到学生姓名和家长电话
- **THEN** 工作模型只写“家长沟通涉及学生个人信息”，不保存姓名和电话，并建议用户决定是否把这类对话排除

#### Scenario: 用户要求删除分析结果
- **WHEN** 用户说“把关于报价的分析都删掉”
- **THEN** Agent 删除工作模型中相关条目及其衍生规则，并列出被删除的条目编号
