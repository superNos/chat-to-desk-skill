## Purpose

让工作台在试用后根据真实使用情况持续调整，并让用户查看、修改、限定或删除系统学到的规则，避免工作台随时间偏离用户实际工作。

## ADDED Requirements

### Requirement: 调整建议基于使用证据
技能 SHALL 要求 Agent 在用户授权的范围内回顾工作台的实际使用（例如哪些入口被使用、哪些输入去向被改正、哪些结果被反复找回、哪些交接失败），并据此提出增加、修改或移除元素的建议。每条建议 MUST 写明依据；没有使用证据时 MUST NOT 以“完善功能”为理由增加元素。

#### Scenario: 某个入口长期未使用
- **WHEN** 试用期内某个输入框从未被使用
- **THEN** Agent 建议移除或询问原因，而不是继续扩展它

#### Scenario: 用户反复手动纠正去向
- **WHEN** 用户多次把“修改结果”类输入从新工作改为继续原工作
- **THEN** Agent 提出调整默认去向或增加选择提示的建议，并说明这些纠正记录

### Requirement: 调整须经用户确认并留下记录
技能 SHALL 要求每次工作台调整在实施前取得用户确认，实施后 MUST 在工作台说明的调整记录中写明改了什么、依据、确认时间。用户拒绝的建议 MUST 被记录，且相同证据下不重复提出。

#### Scenario: 用户拒绝建议
- **WHEN** 用户拒绝“增加按客户筛选”的建议
- **THEN** Agent 不实施该调整，记录拒绝，在出现新的使用证据前不再提出

### Requirement: 用户管理学到的规则
技能 SHALL 要求每条学到的规则有依据、适用范围和状态，用户 MUST 能对每条规则选择保留、修改、限定范围或删除。被删除的规则 MUST 立即停止使用；被限定范围的规则 MUST 只在该范围内使用。保存或修改规则需要用户对保存的授权。

#### Scenario: 用户限定规则范围
- **WHEN** 用户把“回复使用正式语气”限定为只适用于某一位客户
- **THEN** 工作台只在处理该客户的工作时应用这条规则

#### Scenario: 用户删除规则
- **WHEN** 用户删除一条规则
- **THEN** 后续交接内容和 Agent 执行都不再使用该规则，工作台说明记录这次删除

### Requirement: 规则不能扩大授权
技能 SHALL 规定学到的规则只描述工作方式和偏好，MUST NOT 授予发送、提交、付款、发布、删除或扩大历史读取范围等权限。即使规则表述为“总是直接发送”，外部影响动作仍 MUST 每次单独确认。

#### Scenario: 规则试图代替确认
- **WHEN** 用户曾说过“以后这类回复直接发出去就行”，Agent 将其记为偏好
- **THEN** Agent 向用户说明该偏好不能代替每次发送确认，工作台仍在发送前请求确认
