## Purpose

提供可选的本机运行支持，让 Agent 为某位用户生成的工作台页面能在本机打开、保存记录、把交接交给 Agent 或生成可复制内容、取回结果并如实记录状态；它只处理与工作内容无关的事，不决定页面上有什么。

## ADDED Requirements

### Requirement: 运行支持不内置页面或工作内容
运行支持 SHALL 只提供页面服务、记录保存、交接、状态记录和安全检查。它 MUST NOT 包含任何页面布局、栏目、职业字段、功能清单或示例页面；工作台的页面和配置 MUST 由 Agent 按该用户的工作台说明生成，并放在用户指定的本机目录，MUST NOT 放进技能目录。技能目录 MUST NOT 含页面、样式或图片文件。

#### Scenario: 工作台目录没有首页
- **WHEN** 用户指定的工作台目录里还没有 Agent 生成的首页
- **THEN** 运行支持的检查报告缺少首页，而不是提供一个默认页面

#### Scenario: 检查技能目录
- **WHEN** 自动检查扫描技能目录
- **THEN** 运行支持目录只允许两个与工作内容无关的文件，出现页面、样式或图片文件即不通过

### Requirement: 只交接到用户确认的目标
运行支持 SHALL 只把交接交给工作台配置里列出的目标。目标对应的平台对话编号 MUST 只从配置读取，页面 MUST NOT 能看到或指定对话编号。配置中每个目标 MUST 写明三项能力（发起工作、继续同一工作、取回结果）的核实结果，只能是已核实、不支持或待核实。

#### Scenario: 页面请求未配置的目标
- **WHEN** 页面发起一次交接，目标名不在配置里
- **THEN** 运行支持拒绝这次交接，不生成交接记录

#### Scenario: 页面读取状态
- **WHEN** 页面读取工作台状态
- **THEN** 返回的目标信息包含名称和能力核实结果，不包含对话编号

### Requirement: 只在能力已核实时直接交付和取回
运行支持 SHALL 只在目标使用已实现的直接交付方式且对应能力已核实时，直接把交接交给 Agent 或自动取回结果；其余情况 MUST 生成可复制的交接内容并记为需手动完成。发起已核实但取回未核实时，交接 MUST 停在有证据的状态并提示用户手动粘贴结果。直接交付过程中平台发来的执行命令、修改文件或权限请求 MUST 一律拒绝，并提示用户到平台里处理。

#### Scenario: 能力待核实的目标
- **WHEN** 用户向一个三项能力都待核实的目标发起交接
- **THEN** 运行支持生成交接内容，状态为需手动完成，不尝试联系任何平台

#### Scenario: 直接交付时平台请求执行命令
- **WHEN** 交给 Codex 对话的这一轮里，Codex 请求执行命令或修改文件
- **THEN** 运行支持拒绝该请求，并在这条交接上提示用户到 Codex 里处理

#### Scenario: 真实环境核实
- **WHEN** 维护者用隔离的临时配置目录和只用于测试的临时 Codex 对话核实直接交付
- **THEN** 发起和取回各至少成功一次后才在说明中写“维护者核实过”，并注明版本；未做过的环节写未验证

### Requirement: 状态记录有证据且不倒退
运行支持 SHALL 为每条交接记录状态、每次变化的证据和时间、结果及其来源。需手动完成、已发送、已开始、已完成 MUST 只往前推进；待确认和失败 MUST 单独记录；缺少证据时 MUST 保留上一个状态并另外标记最新情况未知。结果需要用户决定时 MUST 记为待确认，用户表示已处理后才记为已完成。

#### Scenario: 已完成后又收到较早的事件
- **WHEN** 一条交接已记为已完成，随后才收到“已开始”的事件
- **THEN** 状态保持已完成

#### Scenario: 已有结论后又收到过程消息
- **WHEN** 一条交接已取回结果、正等用户确认，随后才收到平台的“已开始”消息
- **THEN** 状态保持待确认，同一轮的结果不重复保存，用户仍可确认

#### Scenario: 用户已手动带回结果后平台才返回
- **WHEN** 用户已把对话里的回复粘贴回来并确认已处理，之后重新查询读到同一轮的回复
- **THEN** 不新增一版结果，不改变状态和用户的确认，只提示平台的回复与已保存的是否一致

#### Scenario: 结果超过保存上限
- **WHEN** 取回的结果超过单条结果的保存上限
- **THEN** 只保存前面部分并标明不完整，状态记为待确认，提示用户到原对话查看完整内容，不记为已完成

#### Scenario: 等待超时
- **WHEN** 直接交付后等待这一轮结束超过配置的时间
- **THEN** 状态保持上一个有证据的状态，标记最新情况未知，不记为失败

#### Scenario: 消息已写出但没等到确认
- **WHEN** 运行支持已把这条消息写给平台，随后平台没有回应或进程退出
- **THEN** 不记为失败，也不记为已发送；标记最新情况未知，并提示用户先到平台对话里查看是否已收到，再决定是否重新发起

### Requirement: 本机安全边界
运行支持 SHALL 只监听本机环回地址，且只接受本机地址作为 Host。它 MUST 每次启动生成只保存在内存中的随机令牌，所有接口请求 MUST 带该令牌；写操作 MUST 来自同源页面，跨站请求 MUST 被拒绝。请求体、单段文字和单条记录 MUST 有大小上限。它 MUST 只提供工作台页面目录中允许类型的文件，MUST NOT 提供配置、状态数据、隐藏文件或页面目录以外的文件（含路径穿越和指向目录以外的软链接）。页面 MUST 带只允许连接本机的内容安全策略。运行支持 MUST NOT 执行由用户输入拼出的命令；记录文件 MUST 只有本人可读写，日志 MUST NOT 记录请求内容。

#### Scenario: 其它网站尝试调用接口
- **WHEN** 浏览器中另一个网站向工作台接口发出写请求
- **THEN** 运行支持因来源不同或缺少令牌而拒绝

#### Scenario: 页面请求私有文件
- **WHEN** 有请求尝试读取工作台配置、状态数据或用 `..` 访问上级目录
- **THEN** 运行支持拒绝，不返回文件内容

#### Scenario: 请求过大
- **WHEN** 请求体超过上限
- **THEN** 运行支持拒绝请求，不写入任何记录

### Requirement: 覆盖和删除用户记录需确认
运行支持 SHALL 允许页面保存工作台记录；覆盖已有记录或删除记录时，请求 MUST 带有用户已确认这一次的标记，缺少标记时 MUST 拒绝。

#### Scenario: 页面未经确认删除记录
- **WHEN** 页面请求删除一条记录但没有带确认标记
- **THEN** 运行支持拒绝，记录保留

#### Scenario: 页面用新建的方式写一条已存在的记录
- **WHEN** 页面请求保存的记录名已经存在，且没有带覆盖和确认标记
- **THEN** 运行支持拒绝，原记录保留
