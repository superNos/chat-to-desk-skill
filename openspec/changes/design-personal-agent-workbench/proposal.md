## Why

人们越来越多地通过 Codex、Claude、WorkBuddy 等 Agent 完成日常工作，但工作分散在大量对话里：背景要反复说明，结果难以找回，进行中的事情也难以管理。已有的一些做法（例如开发者用来分派和跟进多项任务的台账）只适合某一种工作方式，不能直接推广给工作内容不同的用户。

需要一个更抽象的技能：它不交付统一的工作台，而是指导用户自己的 Agent 研究用户过去的工作，与用户共同设计、搭建并持续调整专属工作台，再通过工作台把用户操作交还给 Agent 执行。

v0.1.0 允许产出“只是一份文档或一段说明”，用户看过两个演示后明确指出这不是他要的：产出应该是一个能在浏览器里打开、能发起和继续工作、能看到状态和结果的工作台。v0.2.0 据此修正：主要产出必须是可交互的本机工作台，工作台的内容仍然因人而异。

## What Changes

- 新增技能 `chat-to-desk`（原名 `personal-agent-workbench`），用于指导 Agent 完成“确认范围 → 理解工作 → 用户校准 → 设计工作台 → 小范围试用 → 持续调整”的循环。
- 技能只规定分析方法、设计判断、交互约定、隐私授权和质量标准；工作台包含哪些功能、对象、字段、页面和流程，均由具体用户的工作证据和确认结果决定。
- 技能的主要产出是一个可交互的本机工作台：在浏览器打开，能发起新工作、继续某件工作、修改结果，并能看到状态和 Agent 返回的结果。Markdown 记录或交接文字只能作为工作台里的数据或导出内容。历史很少的用户得到一个很小的工作台（一个发起入口和一处找回结果的地方），不是一份文档。
- 新增“工作模型”和“工作台说明”两类由 Agent 维护、用户可审阅的本地记录，用于说明每项设计的依据、交互约定和已确认规则。
- 新增可选的本机运行支持（只用 Python 标准库）：只在 127.0.0.1 提供 Agent 为该用户生成的页面、保存工作台记录、按配置把交接交给 Agent 或生成可复制内容、读取结果并如实显示状态。它不含任何页面布局、职业字段或功能清单。首个直接交付适配器是 Codex；其它平台走复制交接，标为未验证。
- 新增平台适配说明：分别核实历史读取、发起工作、继续同一工作、取回结果四项能力；能力缺失时降级为可复制的交接内容，并如实显示需要手动完成。
- 新增虚构案例和评估材料，用于证明不同用户会得到不同工作台，并检查 Agent 是否套用了通用模板。
- “多 Agent 开发总控”只作为一类用户可能得到的一种工作台案例，不是默认产物。

## Capabilities

### New Capabilities

- `work-history-understanding`：在用户授权范围内分析历史工作，建立带证据的工作模型，并与用户校准哪些判断和规则成立。
- `personal-workbench-design`：根据已确认的工作模型设计并搭建专属的可交互工作台，说明设计依据，避免默认模板；证据很少时给出最小工作台（“暂不需要复杂工作台”指功能少，不指不做工作台）。
- `workbench-agent-interaction`：规定工作台中的输入去向、Agent 执行或交接、结果回写（含手动粘贴回结果）、状态展示和用户确认边界。
- `workbench-evolution`：根据真实使用情况提出工作台调整建议，经用户确认后修改，并让用户管理系统学到的规则。
- `workbench-local-runtime`：可选的本机运行支持，负责提供页面、保存记录、交付适配（手动复制与 Codex）、状态记录和本机安全边界，不决定页面上有什么。

### Modified Capabilities

无。

## Impact

- 新增 `skills/chat-to-desk/` 下的技能说明、参考指南、虚构案例和 Agent 元数据；v0.2.0 起另含 `scripts/workbench.py` 与 `scripts/client.js` 两个与工作内容无关的运行支持文件。
- 新增用于评估技能输出的虚构历史样本、检查清单和必要的轻量校验脚本或测试；v0.2.0 重跑两个前向演示，产出真实启动的工作台和截图，并补齐运行支持的自动测试。
- README、CHANGELOG、安全说明和贡献说明需要说明技能的定位、隐私边界和安装方式。
- 新增只用 Python 标准库的发布前检查，覆盖敏感信息、图片元数据、隐藏文件和内部链接。
- 本变更最早在一个多 Agent 开发总控技能的仓库中开发，本发布包只包含新技能，不包含、不修改也不依赖那些技能。
